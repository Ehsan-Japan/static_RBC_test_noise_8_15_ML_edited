Deck and the figures it uses, one folder per slide.

THE DECK IS THE ONE AT THE PROJECT ROOT,
SSDMpresentation_Ehsan_2026.pptx.  The copy in this folder is a
mirror, rewritten by the build scripts; never edit it directly.

Folder names carry the slide number, so they go stale whenever a slide is
inserted or retitled.  rename_slide_folders.py derives the right names from
the deck itself:
  python SSDM_deck/rename_slide_folders.py            # show the plan
  python SSDM_deck/rename_slide_folders.py --apply    # do it

Build scripts here — run them all with:
  python SSDM_deck/build_deck.py
  deck_common.py            shared paths + find_slide(): the scripts locate
                            slides BY TITLE, never by index, because the
                            deck gained a slide at position 3
  make_intro_slides.py      copies slide 3 of the SSDM 2024 deck (quantum
                            dots as a qubit platform, with its notes) in
                            front of the problem slide, then normalises the
                            two titles: the pasted one loses its explicit
                            32 pt for a clone of a normal title box, and the
                            problem slide stops being a second
                            "Introduction".  Idempotent.
  make_measurement_slide.py            "Ray-based measurement": panel +
                            fig_data_split
  make_model_caption.py       the caption under "Our model"
  make_probability_slide.py            "From probability to lines", from the
                            p2l_* panels
  make_slide_pictures.py    "Our model" probability panel and the
                            "Results" chart
  make_notes.py             speaker notes on all 12 slides,
                            checked against each slide's title
  make_pdf.py               ALWAYS LAST — writes, next to the deck,
                            SSDMpresentation_Ehsan_2026.pdf (slides) and
                            ..._notes.pdf (slide + its notes, for rehearsal)
  make_probability_explainer.py  writes explainer_probability_to_lines.pdf
Figures come from  python paper_figures/make_figures.py  and are NOT
rebuilt by build_deck.py.
Images are extracted from the .pptx itself, so they are exactly
what each slide shows.  Where a vector version of the same
figure exists it is copied alongside as .pdf.

          TWO colours on white, plus a band:
            black  the ground truth transition line (1 px wide)
            red    the model's output, after the P > 0.4 cut
            grey   the tolerance band, every pixel within tau of the truth
          The band is what makes tau visible.  tau is symmetric: precision
          dilates the TRUTH, recall dilates the PREDICTION; the drawn band
          is the precision side.  The probability map uses magma, the
          same map as slide 8.  Axes are the device's real gate window, V1 -1.0 ..
          -0.2 mV and V2 -0.4 .. 0.4 mV, with a dotted grid over the image.
          NOTE 01_fig_probability_to_lines.* is the OLD merged figure and
          still carries the old teal/red/plum deck palette.
